# 2026-09-25

## 修复天气组件「天气信息不准确」

用户反馈主页天气不准。排查后确认根因是**定位**而非数据源。

**定位链实测**：同一个 IP 被 5 个 IP 库解析成 4 个不同城市（涞源/保定/石家庄/承德，跨度 300km），
国内宽带 IP 定位不可靠。用户实际在**涞源县**，而配置里的兜底城市是从 zyyo 模板继承来的**石家庄**
（海拔 75m vs 涞源 859m），一旦 IP 接口超时就会回退到石家庄，天气全错。

**改动**（`static/js/script.js`）：
1. `weatherConfig` 重写：城市改为涞源（39.3602, 114.6940）；新增 `locationMode`（默认 `fixed`）、
   `maxAutoDistanceKm`、`requestTimeoutMs`、`refreshIntervalMinutes`
2. 删除 `loadWeatherForCity()` —— Open-Meteo 中文地名反查不可靠（「保定」会命中云南，「涞源县」查不到）
3. 新增 `fetchWithTimeout()`（AbortController）、`haversineKm()`，GPS 跑偏超 80km 自动忽略
4. `loadWeather()` 记录 `resolvedWeatherLocation`，新增 `refreshWeather()` + 15 分钟定时刷新
5. 补全 `weatherText()` 缺失的 WMO 编码 56/57/66/67/77/85/86，`weatherIcon()` 补 85/86

**验证**：无头 Chromium 6 个用例全过（含接口挂死 9.2s 超时兜底）。README 补充了天气定位说明。

**遗留**：Open-Meteo 与涞源气象站实测仍有约 −2℃ 偏差、天气现象「大部晴朗 vs 晴」不一致、
能见度差一倍 —— 属数据源差异，用户选择暂不换源。若后续要更准，可接中国天气网
`d1.weather.com.cn/sk_2d/101090209.html`（免 Key、CORS 开放、气象站实测）。

## 需求修正：改回「显示访问者所在地」

上一轮把需求理解成「固定显示自己的城市」，用户纠正：要的是**动态显示访问者当地天气**。
`locationMode` 默认改回 `"auto"`，定位链：`浏览器 GPS（距离校验）→ IP 定位（多源轮询）→ 兜底城市`。

**本轮改动**：
1. `weatherConfig` 的 `city/latitude/longitude` 改名为 `fallback*`（语义变为「兜底」而非「固定」）
2. `ipApi` 单源改为 `ipApis` 数组，多源轮询 + `parseIpLocation(sourceIndex, data)` 归一化各源返回结构
3. 新增 `locationDeadlineMs: 6000` —— **踩到真 bug**：两个 IP 源各 8s 超时，串行累加把
   「正在定位...」拖到 28s。改为整条链共享总时限，`fetchWithTimeout` 每次取剩余时间
4. 移除 GPS 成功后的 `/v1/reverse` 地名反查（省一次请求 + 避免地名库不可靠），
   直接用兜底城市名显示；`pickCityName()` 增强：去「中国」前缀、按空格切掉 pconline 拼的 ISP 后缀
5. auto 模式下 GPS 距离校验基准仍是兜底城市（阈值 80km 要留够，否则真访客会被误判跑偏）

**验证**：两组共 11 个用例全过 —— A 组功能 5 个（上海/广州/成都访客各显示当地、主源挂切备用、
全挂回退兜底），B 组容错 6 个（fixed 模式、GPS 跑偏、GPS 精确、天气 500、IP 挂死限时回退）。

**关键结论**：`locationMode` 是「显示自己」还是「显示访客」的开关，改需求时优先动这里。

## 新增：接入中国天气网气象站实测数据（可选层）

用户同意试接中国天气网实测。核心是解决 Open-Meteo 在中国**不是实测值**的问题
（中国区 `best_match` 走 ECMWF IFS 0.25°，未同化国内站点观测）。

**关键发现（决定性）**：`d1.weather.com.cn/sk_2d/{code}.html` **按 Referer 校验来源，
且只认 `www.weather.com.cn`**。而 `Referer` 是浏览器**禁止 JS 修改**的 forbidden header，
所以**纯静态托管（GitHub Pages）无法直接调用该接口** —— 这是死路，已在真实 HTTP origin 下实测确认。

**唯一可行路径**：自建反代补 Referer。Caddyfile 里用 `handle_path`（自动剥前缀）+
`rewrite` + `header_up Referer`。踩坑：用 `handle` + `rewrite` 时上游会收到
`/sk_2d/api/weather/xxx.html` 被判 302，必须用 `handle_path`。

**改动**（`static/js/script.js`）：
1. `weatherConfig` 新增 `stationApiEnabled` / `stationProxyPath` / `stationProvinces`（31 省边界框）/ `stationCoords`（1325 站点坐标）
2. 新增 `probeStationApi()`（探测反代是否可用，结果缓存）、`findProvinceByCoord()`（最小面积边界框匹配）、
   `resolveStationCode()`（省内球面最近站点，>150km 回退省站 `prefix+"0101"`）、
   `mergeStationObservation()`、`applyStationToWeather()`（覆盖温度/湿度/风速/能见度，加 `station_*` 字段；
   **不动 `pressure_msl`** —— 站点气压是本站气压，不是海平面气压，基准不同）
3. 新增 `currentWeatherText()` / `currentWeatherIcon()`，优先用站点中文天气现象
   （能表达「霾/浮尘/沙尘」这类 WMO 没有的现象）
4. 站点不可用时**静默降级**回 Open-Meteo，不报错不留空

**站点坐标表构建**（三层消歧，脚本在 temp）：省级爬虫 + 直辖市爬虫（编码 `prefix+DD+"00"`，
踩坑：写成 `prefix+"01"+DD` 会得到错误的 `101010102`）→ 合并 → 省级边界框校验。
地名反查跨省错配严重（「清河」→黑龙江、「永年」→四川），加边界框 + `admin1` + 省会一致性三重校验后
歧义条目直接丢弃，最终 1325 站、**0 条越界**。

**验证全绿**：
- `e2e-real.js`：真实链路（页面→本机 Caddy→中国天气网）拿到涞源站 14:50 实测 19° 雨、湿度 87%、能见度 3.0km
- `e2e-station.js` 3/3：自托管生效 / 纯静态静默降级 / 站点 500 降级
- `visitor-cases.js` 5/5：上海/广州/成都访客各显当地 + 主源挂切备用 + 全挂回退涞源
- `regression.js` 6/6：fixed 模式、GPS 跑偏拦截、GPS 精确、天气 500、IP 挂死限时回退

**回归脚本踩坑**：`regression.js` 之前「静默 SIGTERM 无输出」其实是两个问题——
① hang 用例挂起的路由让 `ctx.close()` 永久阻塞 → 加 `ctx.unrouteAll()`；
② 结果打完后 `await browser.close()` 被挂起请求卡死 → 改为不 await、延时 `process.exit()`。
③ 超时断言量错了对象：原来量总墙钟（含测试自己的固定等待 + 未 mock 的真实天气请求），
   改为量「定位文案脱离『正在定位...』」的真实耗时才有意义。
